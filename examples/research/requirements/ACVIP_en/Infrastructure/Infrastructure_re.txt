The system shall define a top-level AADL package named Infrastructure, which shall establish an explicit import dependency on the SEI pre-defined property package to support configuration of SEI-namespaced architecture properties. The Infrastructure package shall encapsulate all base infrastructure elements, including communication bus types and implementations, power transmission bus types and implementations, and power source system components and their implementations, and shall not contain application-specific functional logic components, executable thread components, or standalone data type definitions. All cross-package references within the Infrastructure package shall be limited to elements imported from the SEI package, and all component-to-bus bindings within the package shall reference locally defined bus elements to eliminate unapproved external dependencies.

The system shall define a system-type component named PowerSource, which functions as a dedicated infrastructure power supply unit. The PowerSource component shall expose exactly one external provided bus access feature named powerOut, which acts as the sole external interface of the component. The powerOut feature shall be typed to bind to the generic implementation of the power transmission bus. The PowerSource component shall configure the SEI-defined PowerSupply property on the powerOut feature with a value of 10.0 W, to specify the rated power output capability of the interface. The system shall define a system implementation named PowerSource.i for the PowerSource component type, which shall contain no internal subcomponents, internal connection paths, or private internal features, representing a minimal standalone power supply implementation.

All digital data communication flows between connected end components shall be transmitted over bound data communication bus implementations, with each bus acting as a passive medium to carry data payloads between connected component ports without in-bus data processing, modification, or routing logic. All power transmission flows shall originate from the powerOut provided bus access interface of the PowerSource component, propagate through the connected generic power bus implementation, and deliver electrical power to downstream components connected to the same power bus. No digital data transmission flows shall be carried over the power transmission bus, and no power transmission flows shall be carried over the dedicated data communication buses to ensure functional separation between power and data delivery paths.

The two dedicated data communication buses shall enforce bandwidth-governed transmission scheduling to meet deterministic performance constraints. Routine steady-state bus traffic shall be scheduled to operate within the configured bandwidth budget, and total instantaneous bus traffic shall never exceed the configured bandwidth capacity to prevent transmission blocking, data loss, or unbounded transmission latency. The power transmission bus shall provide continuous, non-scheduled power delivery with no time-based transmission scheduling requirements, as it does not carry time-sensitive digital data payloads. No additional periodic or aperiodic thread scheduling configurations, deadline constraints, or latency requirements shall be defined for elements within the Infrastructure package, as all contained elements are passive bus infrastructure and static power supply components without executable thread or process logic.

The Infrastructure package shall not define standalone AADL data components, as all data payloads transmitted over the data communication buses shall be constrained by the per-bus Data_Size property to a maximum single-frame payload of 8 bytes. The system shall define three distinct bus types within the Infrastructure package. The first bus type, named CanBus, shall represent a CAN-based serial data communication bus, and shall have a corresponding bus implementation named CanBus.i with no internal structural elements, subcomponents, or internal connections. The CanBus type shall set the Data_Size property to 8 Bytes to define the maximum single-frame payload size, shall set the SEI::BandWidthBudget property to 512.0 KBytesps to define the allocated steady-state operating bandwidth, and shall set the SEI::BandWidthCapacity property to 768.0 KBytesps to define the maximum allowable burst bandwidth capacity. The second bus type, named Bus1553, shall represent a MIL-STD-1553 based serial data communication bus, and shall have a corresponding bus implementation named Bus1553.i with no internal structural elements, subcomponents, or internal connections. The Bus1553 type shall set the Data_Size property to 8 Bytes for maximum single-frame payload, shall set the SEI::BandWidthBudget property to 512.0 KBytesps for steady-state bandwidth allocation, and shall set the SEI::BandWidthCapacity property to 768.0 KBytesps for maximum burst bandwidth capacity. The third bus type, named power, shall represent a dedicated power transmission bus with no digital data communication capability, and shall have a corresponding bus implementation named power.generic representing a general-purpose power delivery bus with no internal structural elements, subcomponents, or internal connections. The power bus type shall not configure Data_Size, bandwidth budget, or bandwidth capacity properties, as it does not carry digital data payloads. All bus implementations within the package shall be structurally passive, with no active logic elements, to serve as standardized connection media for cross-component power and data interconnection.
