The system shall define a top-level publicly accessible AADL package named Controller. The Controller package shall establish explicit import dependencies on three external supporting packages: the DataDictionary package for shared data type definitions, the Infrastructure package for pre-defined communication and power bus interface declarations, and the SEI package for standardized non-functional property definitions. The Controller package shall contain one system type component named SimpleController, and one associated system implementation component identified as SimpleController.i that realizes the SimpleController system type. The SimpleController.i implementation shall not include declarations of nested subcomponents, with all functional, interface, and property definitions specified directly at the system level.

The SimpleController system type shall expose five public external interface features representing required access points and data exchange points. The first interface feature is a required bus access named busIn, which shall connect to the instance i of the bus1553 bus declared in the Infrastructure package. The second interface feature is an input data port named dataIn, which accepts incoming data payloads. The third interface feature is a required bus access named busOut, which shall connect to the instance i of the canBus bus declared in the Infrastructure package. The fourth interface feature is an output data port named dataOut, which transmits outgoing data payloads. The fifth interface feature is a required bus access named powerIn, which shall connect to the generic instance of the power bus declared in the Infrastructure package. The SimpleController system shall define a named end-to-end functional flow path called controllerFlow that traces a logical connection from the dataIn input port to the dataOut output port. The system shall include an EMV2 error model annex that imports standard error types and the FailStop error behavior from the public ErrorLibrary. Within the error propagations clause of the annex, two propagation points shall be declared: an inbound propagation point named datain that carries error types ServiceOmission and ValueError, and an outbound propagation point named dataout that carries error types ServiceOmission and ValueError. Two error flows shall be defined within the propagations clause: an error sink named f1 bound to the datain propagation point that captures ServiceOmission and ValueError faults, and an error source named f2 bound to the dataout propagation point that emits ServiceOmission and ValueError faults. The component-level error behavior state machine shall define two distinct internal error events: an event named serviceommission representing loss of required service, and an event named valueerror representing invalid data value generation. The state machine shall initialize to the Operational state for normal function, and shall define two state transitions: a transition from the Operational state to the FailStop state triggered by the serviceommission event, and a transition from the Operational state to the FailStop state triggered by the valueerror event.

Nominal functional data flow within the SimpleController system shall traverse the defined controllerFlow path, where valid payloads received at the dataIn input port are processed by the system’s internal logic to generate corresponding payloads for transmission through the dataOut output port. The busIn and busOut required bus access points shall provide the physical and protocol layer transport required to support data exchange with external components connected to the respective buses. The powerIn required bus access shall deliver operating power to the component, and shall not carry functional application data payloads. For error-related flow, ServiceOmission and ValueError faults arriving at the datain propagation point shall terminate at the system boundary as captured by the f1 error sink. Internal fault events of type serviceommission or valueerror that occur during component operation shall immediately transition the component to the FailStop state, and the resulting ServiceOmission and ValueError fault conditions shall be propagated outward through the dataout propagation point as defined by the f2 error source. When in the FailStop state, the component shall cease all nominal data processing and output transmission activities.

The SimpleController.i system implementation shall enforce a bounded end-to-end latency requirement applied to the controllerFlow path, such that the total elapsed time between the arrival of a valid input sample at the dataIn port and the transmission of the corresponding processed output value at the dataOut port shall fall within the closed range of 3 milliseconds to 5 milliseconds. The implementation shall enforce a power consumption budget of 4.0 watts for all power drawn through the powerIn bus access interface. The implementation shall comply with a total component mass limit of 1.2 kilograms as defined by the SEI standardized WeightLimit property applied to the system component as a whole.

All data exchanged through the system’s data ports shall conform to pre-defined shared data types imported from the DataDictionary package, with no custom data type definitions declared within the Controller package. The dataIn input port shall exclusively carry values that match the structure and semantics of the SensorData data type from the DataDictionary package, with no unsupported data type conversions permitted at the port interface. The dataOut output port shall exclusively carry values that match the structure and semantics of the BrakeSignal data type from the DataDictionary package, with no unsupported data type conversions permitted at the port interface. All bus access interfaces shall comply with the interface specifications of pre-declared bus instances imported from the Infrastructure package, with no custom bus type definitions declared within the Controller package. The busIn access shall adhere to the electrical, protocol, and timing requirements of the 1553 bus as defined by Infrastructure::bus1553.i, the busOut access shall adhere to the electrical, protocol, and timing requirements of the CAN bus as defined by Infrastructure::canBus.i, and the powerIn access shall adhere to the electrical and interface requirements of the generic power bus as defined by Infrastructure::power.generic. All non-functional property assignments in the system implementation shall reference property definitions imported from the SEI package, with property scope strictly limited to the applicable model elements: the WeightLimit property shall apply to the entire SimpleController.i component, and the powerBudget property shall apply exclusively to the powerIn bus access feature. All error modeling constructs used in the EMV2 annex shall reference standard type and behavior definitions from the ErrorLibrary, with no custom error type or behavior state definitions introduced within the Controller package.
