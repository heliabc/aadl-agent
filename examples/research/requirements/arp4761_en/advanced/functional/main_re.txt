The top-level modeling package shall be defined with the path functional::main, with public visibility for all contained elements. This package shall explicitly import required dependent elements, including all public elements from the functional::GenericFunctions package, the WBSPS property set, the functional::WheelBrake::Main package, the functional::Throttle package, the functional::Electrical package, and the functional::Hydraulic package. A top-level system type named Aircraft shall be defined, with no externally exposed features, and a corresponding basic implementation named Aircraft.basic. The Aircraft.basic implementation shall contain six subcomponent instances: a deceleration function instance named decelerate typed to the basic implementation of the DecelerateAircraft system, an electrical power supply instance named electrical typed to the basic implementation of the Electrical system from the functional::Electrical package, a hydraulic power supply instance named hydraulic typed to the basic implementation of the Hydraulic system from the functional::Hydraulic package, an alert function instance named alert typed to the basic implementation of the Generic system from the functional::GenericFunctions package, a steering function instance named steering typed to the basic implementation of the Generic system from the functional::GenericFunctions package, and a status monitoring function instance named status typed to the basic implementation of the Generic system from the functional::GenericFunctions package. A dedicated system type named DecelerateAircraft shall be defined, with the WBSPS::IsFunction property assigned a value of true to mark it as a core aircraft function, and a corresponding basic implementation named DecelerateAircraft.basic. The DecelerateAircraft.basic implementation shall contain two subcomponent instances: a wheel braking deceleration instance named DecelerateWheels typed to the basic implementation of the DecelerateWheels system from the functional::WheelBrake::Main package, and a throttle-based deceleration instance named DecelerateThrottle typed to the DecelerateThrottle system from the functional::Throttle package. Error behavior definitions for elements in this package shall depend on the WBSFunctionalErrorLib error library: the Aircraft.basic implementation shall reference the Twostate error behavior definition from this library, the DecelerateAircraft system type shall reference error type definitions from this library for propagation rules, and the DecelerateAircraft.basic implementation shall reference the TwostateWBS error behavior definition from this library for composite error state logic.

The DecelerateAircraft system type shall expose five untyped input features as its external interface, named fromElectrical, fromHydraulic, fromAlert, fromSteering, and fromStatus, for receiving fault status signals from cross-linked aircraft subsystems. Error propagation rules for the DecelerateAircraft external interface shall be defined as follows: the fromElectrical feature acts as an inbound error propagation point that accepts errors of the AnyFunctionalError type, the fromHydraulic feature acts as an inbound error propagation point that accepts errors of the HydraulicErrors type, the fromAlert feature acts as an inbound error propagation point that accepts errors of the AnyFunctionalError type, the fromSteering feature acts as an inbound error propagation point that accepts errors of the AnyFunctionalError type, and the fromStatus feature acts as an inbound error propagation point that accepts errors of the AnyFunctionalError type. All subcomponents contained in the Aircraft.basic implementation shall conform to interface requirements: the electrical, hydraulic, alert, steering, and status subcomponents shall each expose an untyped output feature named isFailing to transmit local fault status to connected components. All subcomponents contained in the DecelerateAircraft.basic implementation shall conform to interface requirements: the DecelerateWheels subcomponent shall expose five untyped input features matching the parent DecelerateAircraft external interface, named fromElectrical, fromHydraulic, fromAlert, fromSteering, and fromStatus, to receive forwarded fault signals; the DecelerateThrottle subcomponent shall expose a Failed error state to support composite error state calculation for the parent component.

All cross-component connections shall be defined as unidirectional, point-to-point port mappings with no intermediate processing nodes. At the Aircraft.basic hierarchy level, five dedicated connections shall be established to route fault signals from support subsystems to the deceleration function: the isFailing feature of the electrical subcomponent shall connect to the fromElectrical feature of the decelerate subcomponent, the isFailing feature of the hydraulic subcomponent shall connect to the fromHydraulic feature of the decelerate subcomponent, the isFailing feature of the alert subcomponent shall connect to the fromAlert feature of the decelerate subcomponent, the isFailing feature of the steering subcomponent shall connect to the fromSteering feature of the decelerate subcomponent, and the isFailing feature of the status subcomponent shall connect to the fromStatus feature of the decelerate subcomponent. At the DecelerateAircraft.basic hierarchy level, five internal connections shall be established to forward incoming fault signals to the wheel braking subfunction: the fromElectrical feature of the parent DecelerateAircraft component shall connect to the fromElectrical feature of the DecelerateWheels subcomponent, the fromHydraulic feature of the parent DecelerateAircraft component shall connect to the fromHydraulic feature of the DecelerateWheels subcomponent, the fromAlert feature of the parent DecelerateAircraft component shall connect to the fromAlert feature of the DecelerateWheels subcomponent, the fromSteering feature of the parent DecelerateAircraft component shall connect to the fromSteering feature of the DecelerateWheels subcomponent, and the fromStatus feature of the parent DecelerateAircraft component shall connect to the fromStatus feature of the DecelerateWheels subcomponent. No direct data or fault signal connections shall be established between the DecelerateThrottle subcomponent and other subcomponents or external interface points in the current implementation.

No periodic task scheduling rules, fixed execution time budgets, or guaranteed end-to-end transmission latency values shall be defined for components within the current package scope. Fault signal transmission across connections shall follow an event-driven trigger mechanism, with composite error state evaluation executed immediately upon reception of state changes from dependent subcomponents. Composite error state transition logic shall follow defined Boolean OR conditions without priority weighting between fault sources. For the DecelerateAircraft.basic implementation, the component shall transition to the Failed state immediately when any of the following conditions are met: the DecelerateWheels subcomponent enters the Failed state with an associated TotalWBLossAnunciated fault type, the DecelerateWheels subcomponent enters the Failed state with an associated TotalWBLossUnanunciated fault type, or the DecelerateThrottle subcomponent enters the Failed state. For the Aircraft.basic implementation, the top-level aircraft system shall transition to the Failed state immediately when the decelerate subcomponent enters the Failed state. No additional fault recovery, fault masking, or delayed state transition logic shall be applied in the current implementation.

No custom structured data types shall be defined within the functional::main package scope. All features used for cross-component connection shall be defined as untyped features, used exclusively for transmitting fault state events without carrying structured application payload data. No dedicated bus components, bus access protocols, or bus binding rules shall be defined within the current package scope. All cross-component connections shall use direct port-to-port mapping without routing through abstracted communication bus infrastructure, with no defined protocol encapsulation, bus arbitration, or data framing requirements for transmitted signals.
