The system modeling framework shall define a standalone property set module named WBSPS, which acts as a global reusable property definition repository accessible to all subsequent AADL packages, component types, component implementations, connections, and other modeling elements across the entire model hierarchy. The WBSPS property set shall establish a dependency on the AADL core language predefined standard data type AadlBoolean, and shall not require any other user-defined packages, property sets, component models, or bus definitions as prerequisite dependencies.

The WBSPS property set module shall not declare any component type, component implementation, data port, event port, event data port, access interface, subcomponent, or internal interconnection structure. No externally exposed service interaction points shall be defined within this property set, and all elements contained in WBSPS shall be referenced as global attribute identifiers or custom type identifiers rather than interactive interface endpoints for component communication.

The definition scope of the WBSPS property set shall not specify concrete functional processing components, data source endpoints, data sink endpoints, port connections, or data transfer links. No binding constraints on end-to-end data flow routes, data transmission directions, or data forwarding rules shall be imposed within this property set.

The definition scope of the WBSPS property set shall not include property definitions related to component scheduling policies, execution period allocation, dispatch offset configuration, worst-case execution time budgets, communication latency limits, or end-to-end timing constraints. No mandatory scheduling rules or timing performance requirements for modeled system elements shall be specified within this property set.

The WBSPS property set shall define three core modeling elements in strict sequence. First, it shall define an inheritable boolean property named IsFunction, which is typed by the core AadlBoolean type and applies to all categories of AADL modeling elements, to mark whether a target model element carries functional logic semantics. Second, it shall define a custom enumeration data type named PhaseType, whose legal enumeration literals are fixed in order as Taxi, Takeoff, RejectTakeoffBeforeV1, RejectTakeoffAfterV1, Climb, Cruise, Descent, TouchAndGo, and Landing, to represent the complete set of operational phases covered by the wheel brake system across the full flight envelope. Third, it shall define an enumeration-typed property named Phase, which takes WBSPS::PhaseType as its value type and applies to all categories of AADL modeling elements, to assign the corresponding operational phase identifier to any target modeling element. The WBSPS property set shall not define custom bus types, bus implementations, bus access interfaces, or bus-associated property constraints within its definition scope.
