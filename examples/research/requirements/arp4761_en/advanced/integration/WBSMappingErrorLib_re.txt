The system shall define a public AADL package named WBSMappingErrorLib, which serves as a dedicated shared library for cross-layer error mapping definitions and base error behavior specifications within the wheel brake system error modeling framework. This package shall establish formal dependencies on two pre-existing public error library packages to support cross-package error type reference via fully qualified type names: the WBSImplementationErrorLib package that provides canonical implementation-layer error type definitions, and the WBSFunctionalErrorLib package that provides canonical functional-layer error type definitions. The package shall not contain standalone definitions of core AADL component categories including system, process, thread, device, processor, memory, or bus, and shall encapsulate all specialized error modeling logic within an EMV2 annex attached directly to the package root.

The package shall expose reusable EMV2 error modeling artifacts as its only publicly accessible interfaces for reference by other packages in the WBS architecture. The first exposed artifact is the Basic error behavior state machine, which defines a minimal, extensible error state set without embedded state transitions, error events, or propagation points, to support consistent error state definition across all WBS components. The remaining exposed artifacts are two typed error mapping sets, which define formal transformation logic for error propagations crossing the boundary between implementation and functional architecture layers. The package shall not define any data ports, event ports, bus access points, or subprogram call interfaces, as it operates as a static design-time library with no runtime interaction points. The Basic error behavior shall define two discrete states: the Operational state designated as the initial state representing normal fault-free operation, and the Failed state representing a faulted condition where the associated component cannot deliver intended functionality.

The error mapping logic defined in the package shall govern bidirectional cross-layer error propagation flows between the WBS implementation layer and functional layer. The FunctionToImplementation mapping set shall handle error flows that originate from implementation-layer components and propagate upward to functional-layer components, applying predefined transformation rules to convert implementation-layer error tokens to semantically aligned functional-layer error tokens. This mapping set shall implement a general catch-all flow path that routes any unspecified implementation error, represented by the AnyImplementationError type from WBSImplementationErrorLib, to the generic functional error type AnyFunctionalError from WBSFunctionalErrorLib, alongside four dedicated point-to-point flow paths for specific error conditions: HydraulicLossBlue errors from the implementation layer map directly to HydraulicLossBlue errors at the functional layer, HydraulicLossGreen implementation errors map directly to HydraulicLossGreen functional errors, HydraulicLossComponents implementation errors map directly to HydraulicLossComponents functional errors, and NoService implementation errors map directly to NoService functional errors. The ImplementationToFunction mapping set shall handle error flows that originate from functional-layer components and propagate downward to implementation-layer components, applying parallel transformation rules to convert functional-layer error tokens to semantically aligned implementation-layer error tokens. This mapping set shall implement a general catch-all flow path that routes any unspecified functional error, represented by the AnyFunctionalError type from WBSFunctionalErrorLib, to the generic implementation error type AnyImplementationError from WBSImplementationErrorLib, alongside four dedicated point-to-point flow paths for matching specific error conditions: HydraulicLossBlue functional errors map directly to HydraulicLossBlue implementation errors, HydraulicLossGreen functional errors map directly to HydraulicLossGreen implementation errors, HydraulicLossComponents functional errors map directly to HydraulicLossComponents implementation errors, and NoService functional errors map directly to NoService implementation errors.

The WBSMappingErrorLib package contains no runtime-executable components, schedulable threads, periodic processing tasks, or time-triggered logic, so no scheduling priority assignments, period specifications, execution time budgets, or deadline constraints shall be defined within the package structure. All error mapping rules contained in the package shall be treated as static, zero-latency transformation logic for error propagation analysis, introducing no additional time delay to calculated error propagation paths when referenced by component error models. The Basic error behavior state set defined in the package shall not specify any time-dependent state transition conditions, allowing referencing components to define custom transition timelines aligned with their specific fault response requirements without constraint from the base library.

The package shall not define any native AADL data types, communication bus types, data type representations, or bus protocol specifications within its scope. All error types referenced in the package’s mapping logic shall be imported directly from the two dependent error library packages, with no local redefinition, type modification, or semantic override of imported error types permitted. The two error mapping type definitions shall enforce strict type checking for propagated error tokens, only permitting transformation of error types explicitly listed in the mapping rule sets, with no support for implicit type conversion of unlisted error types. When applied to error propagation connections across architecture layers, the mapping rules shall operate independently of underlying communication bus types or transported payload data types, requiring no bus-specific or data-specific adaptation to function across all valid WBS inter-component connections.
