The top-level system model is contained within a package named wbs, which shall declare explicit import dependencies on supporting packages including bscu, communication, valves, wheel, pump, power, pedals, ARP4761, and EMV2 to access pre-defined component types, safety property sets, and error modeling constructs. The wbs package defines a root system type named wbs with no externally exposed ports or bus access points at the system boundary, and four hierarchical system implementations tied to the wbs type through an inheritance structure. The base implementation wbs.generic defines the common set of subcomponents and core connections shared across all wbs configuration variants. Three specialized implementations extend wbs.generic to support different levels of model fidelity and architecture patterns: wbs.basic provides a high-level abstracted view of hydraulic valving logic, wbs.detailed provides a fine-grained representation of the full hydraulic circuit, wbs.federated extends wbs.detailed to implement a federated avionics architecture for the brake control function, and wbs.ima extends wbs.detailed to implement an integrated modular avionics architecture for the brake control function with attached formal verification claims. The common subcomponents defined in wbs.generic include a pedal input subsystem of type pedals::pedals.generic, an electrical power distribution subsystem of type power::power.generic, three hydraulic pump components of type pump::pump.i designated blue_pump, green_pump, and accumulator respectively, a hydraulic selector valve assembly, a brake system control unit, a wheel brake assembly, and a crew annunciation device of type communication::annunciation.i. The wbs.basic implementation refines three common subcomponents without adding new subcomponents: the brake system control unit is refined to type bscu::bscu.basic, the selector valve assembly is refined to type valves::selector_basic with a Type_Extension classifier substitution rule enabled, and the wheel brake assembly is refined to type wheel::wheel_one_input.i with a Type_Extension classifier substitution rule enabled. The wbs.detailed implementation refines two common subcomponents and adds three dedicated valve subcomponents: the selector valve assembly is refined to type valves::selector_detailed with a Type_Extension classifier substitution rule enabled, the wheel brake assembly is refined to type wheel::wheel_two_inputs.i with a Type_Extension classifier substitution rule enabled, and the added subcomponents consist of a boolean-actuated shutoff valve of type valves::boolean_shutoff named shutoff, a command-actuated shutoff valve for the green hydraulic circuit named green_skid of type valves::cmd_shutoff, and a command-actuated shutoff valve for the blue hydraulic circuit named blue_skid of type valves::cmd_shutoff. The wbs.federated implementation inherits all subcomponent structure from wbs.detailed, and only refines the brake system control unit subcomponent to type bscu::bscu.federated. The wbs.ima implementation inherits all subcomponent structure from wbs.detailed, refines the brake system control unit subcomponent to type bscu::bscu.ima, and attaches Resolute annex proof obligations to validate architectural redundancy properties.

All subcomponents across all wbs implementations shall expose consistent required and provided interfaces to support valid interconnection, with interface compatibility enforced across refinement steps. The accumulator pump shall expose a provided bus access point for pressure output. The electrical power subsystem shall expose two provided bus access points for power distribution, designated line1 and line2. The brake system control unit shall expose two required bus access points for power input designated pwr1 and pwr2, two incoming data ports for pedal position input designated pedal1 and pedal2, and outgoing command ports matched to the requirements of connected valve components for each implementation variant. The pedal input subsystem shall expose two outgoing data ports for pedal position signals designated signal1 and signal2. The selector valve assembly in the base wbs.generic implementation shall expose a required bus access point for accumulator pressure input. For the wbs.basic implementation, the blue_pump and green_pump components shall each expose a provided bus access point for pressure output; the refined selector_basic assembly shall expose two required bus access points for hydraulic input designated blue_input and green_input, three incoming command ports designated Select_Alternate, cmd_nor, and cmd_alt, and one provided bus access point for regulated pressure output; the refined wheel_one_input assembly shall expose one required bus access point for pressure input. For the wbs.detailed implementation and its derived federated and ima variants, the refined selector_detailed assembly shall expose two required bus access points for hydraulic input designated blue_input and green_input, one incoming command port for alternate mode selection designated select_alternate, and two provided bus access points for regulated pressure output designated green_output and blue_output; the boolean shutoff valve shall expose one required bus access point for hydraulic input, one provided bus access point for hydraulic output, and one incoming boolean command port designated boolean_input; each command-actuated skid valve shall expose one required bus access point for hydraulic input, one provided bus access point for modulated pressure output, and one incoming command port designated cmd_input; the refined wheel_two_inputs assembly shall expose two required bus access points for pressure input designated blue_input and green_input. The crew annunciation device shall expose interfaces to receive fault status data from connected components to support crew alerting. All subcomponents shall expose a standardized Failed error state to the system-level composite error behavior model to support fault propagation analysis.

Interconnection paths across all implementations shall follow defined unidirectional and bidirectional flow rules to support correct system operation. The core connections defined in wbs.generic include bidirectional bus access connections linking the power subsystem line1 access point to the brake system control unit pwr1 access point, and the power subsystem line2 access point to the brake system control unit pwr2 access point for redundant power delivery; unidirectional port connections linking the pedal subsystem signal1 port to the brake system control unit pedal1 port, and the pedal subsystem signal2 port to the brake system control unit pedal2 port for pedal position signal transfer; and a bidirectional bus access connection linking the accumulator pressure output access point to the selector assembly accumulator input access point for reserve hydraulic pressure delivery. Additional connections defined in wbs.basic include bidirectional bus access connections linking the blue_pump pressure output to the selector blue input, and the green_pump pressure output to the selector green input for primary hydraulic supply; unidirectional port connections linking the brake system control unit Select_Alternate port to the selector Select_Alternate port, the brake system control unit cmd_nor port to the selector cmd_nor port, and the brake system control unit cmd_alt port to the selector cmd_alt port for brake command and mode selection transfer; and a bidirectional bus access connection linking the selector output access point to the wheel input access point for regulated brake pressure delivery. Additional connections defined in wbs.detailed and inherited by its federated and ima variants include a bidirectional bus access connection linking the blue_pump pressure output directly to the selector blue input; a bidirectional bus access connection linking the green_pump pressure output to the shutoff valve input, and a second bidirectional bus access connection linking the shutoff valve output to the selector green input for switched green circuit hydraulic supply; unidirectional port connections linking the brake system control unit Select_Alternate port to both the shutoff valve boolean_input port and the selector select_alternate port for coordinated mode switching; unidirectional port connections linking the brake system control unit cmd_nor port to the green_skid cmd_input port, and the brake system control unit cmd_alt port to the blue_skid cmd_input port for anti-skid command transfer; bidirectional bus access connections linking the selector green_output access point to the green_skid input, and the selector blue_output access point to the blue_skid input for regulated pressure feed to anti-skid valves; and bidirectional bus access connections linking the blue_skid output access point to the wheel blue_input, and the green_skid output access point to the wheel green_input for dual-path modulated brake pressure delivery to the wheel assembly. Fault status signals shall propagate from all active components to the annunciation device, with fault combinations mapped to system-level error states via the composite error behavior logic, where simultaneous failure of the brake system control unit and accumulator, or simultaneous failure of the blue_pump, green_pump, and accumulator, shall map to either annunciated or unannunciated total braking loss states based on the operational status of the annunciation device.

System operation shall be constrained to defined flight phases, with hazard likelihood, classification, and latency requirements aligned to ARP4761 standards. Braking function operation shall be active during the Landing and Rejected Takeoff flight phases for all braking loss related hazards, and during the Takeoff flight phase for inadvertent brake application hazards. Annunciated and unannunciated total wheel braking loss events shall be classified as Hazardous per ARP4761, with an Extremely Improbable qualitative probability objective, referenced to AIR6110 page 35 figure 17, with annunciation latency constrained to allow crew time to select appropriate landing sites for annunciated events, and crew procedures defined to address loss of both normal and reserve braking modes. Partial symmetrical wheel braking loss events shall be classified as Hazardous per ARP4761, with an Extremely Improbable qualitative probability objective, referenced to AIR6110 page 35 figure 17, with command path latency constrained to allow crew to use remaining wheel braking, spoilers, and thrust reversers for deceleration, with additional analysis required to confirm final hazard classification. Asymmetrical wheel braking loss events shall be classified as Catastrophic per ARP4761, with an Extremely Improbable qualitative probability objective, referenced to AIR6110 page 36 figure 17, with asymmetry detection and mitigation latency constrained to prevent development of sufficient yaw to cause runway excursion. Inadvertent wheel brake application events during takeoff shall be classified as Catastrophic per ARP4761, with an Extremely Improbable occurrence likelihood defined via EMV2 properties, referenced to AIR6110 page 37 figure 17, accounting for undetectable low-level brake application that can lead to excessive brake temperature and degraded takeoff performance. The brake system control unit shall sample pedal input signals at a fixed rate sufficient to maintain anti-skid control loop stability, with valve command outputs updated synchronously each control cycle to minimize transport delay between pedal input and brake pressure modulation. For the wbs.ima implementation, formal proof obligations shall be satisfied to verify the architecture contains two independent power supply paths, two independent selector valve assemblies, and two redundant brake system control unit channels to meet redundancy requirements for catastrophic hazard mitigation.

All data types and communication paths shall follow consistent definition rules to support model consistency across refinement levels. Unidirectional port connections shall be used for all signal and command transfers, with data types matched to the interface definitions of imported component packages: pedal position ports shall carry analog scalar values representing pedal displacement, mode select ports shall carry boolean values representing normal or alternate operating mode, and brake command ports shall carry scalar values representing commanded brake pressure. Bidirectional bus access connections shall be used for all physical transfer paths, with dedicated bus types defined for each physical medium: hydraulic pressure buses shall carry fluid pressure state as the primary communicated parameter, used for all connections between pumps, valves, and the wheel assembly; electrical power buses shall carry supply voltage state as the primary communicated parameter, used for all connections between the power subsystem and powered components. Error types used in the EMV2 annex shall be imported from a shared error_library type set, with system-level error behavior referenced from the error_library::wbs behavior definition to support standardized fault propagation across component boundaries. Classifier substitution rules for refined subcomponents in wbs.basic and wbs.detailed shall be set to Type_Extension, requiring all replacement component types to be compatible extensions of the parent component type with fully conformant interfaces, to support incremental model refinement from abstract to detailed views without breaking interconnection integrity.
