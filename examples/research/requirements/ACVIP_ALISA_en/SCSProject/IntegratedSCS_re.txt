A dedicated AADL package named IntegratedSCS shall be defined as the top-level naming container for all sensor control system related model elements, and this package shall explicitly declare import dependencies on two external packages, namely SoftwareParts and PhysicalParts, to enable valid reference to model elements defined in those external namespaces. An abstract system type named SCS, representing the generic sensor control system template, shall be defined within the IntegratedSCS package, with no preconfigured internal structure to support extension across multiple deployment configurations. A system implementation named SCS.singletier0 shall be created for the SCS system type to represent a single-tier deployment configuration; this implementation shall contain four top-level subcomponents, including one instance of the ControlSystem system type named ControlSystem, two independent device instances named sensor1 and sensor2 respectively to represent field sensing units, and one device instance named actuator to represent the field actuation unit, with all subcomponents arranged in a flat deployment hierarchy under this configuration. A standalone abstract system type named ControlSystem shall be defined within the IntegratedSCS package to serve as the aggregation abstraction for control logic and its supporting hardware infrastructure, with no preconfigured internal structure to support variant implementation options. A system implementation named ControlSystem.singletier0 shall be created for the ControlSystem system type to match the single-tier deployment configuration of the top-level SCS; this implementation shall contain two nested subcomponents, including one instance of the DigitalControl system type referenced from the SoftwareParts package named Software to carry core digital control algorithm functions, and one instance of the main_board system type referenced from the PhysicalParts package named Hardware to provide physical computing, storage, and interconnection support for the hosted control software.

All system types defined directly within the IntegratedSCS package, including the top-level SCS type and the nested ControlSystem type, shall not declare externally exposed features such as input ports, output ports, service access points, configuration parameter interfaces, or physical connection points in the current baseline version, with reserved extension space for subsequent interface refinement as functional requirements evolve. All subcomponents contained in the SCS.singletier0 implementation, including sensor1, sensor2, actuator, and the ControlSystem instance, shall not declare component-level external interaction interfaces in the current baseline, and no explicit interface binding between these peer subcomponents shall be configured at this stage. All subcomponents contained in the ControlSystem.singletier0 implementation, including the Software instance referencing the external DigitalControl system and the Hardware instance referencing the external main_board system, shall not declare cross-layer interaction interfaces in the current baseline, and no explicit interface mapping between the software and hardware subcomponents shall be configured at this stage. All subsequent interface additions shall comply with the namespace governance rules of the parent component, and shall maintain full consistency with interface definitions of referenced elements from external dependent packages.

No explicit end-to-end data flow paths shall be defined in the current baseline of the singletier0 configuration under the IntegratedSCS package. No data link mappings shall be configured between the sensor device instances and the control system instance, between the control system instance and the actuator device instance, or between the internal software and hardware subcomponents of the ControlSystem instance at this stage. Reserved configuration space shall be retained for all data flow links, and subsequent data flow definitions shall follow the inherent hierarchical flow direction from field sensing endpoints to control processing nodes then to field actuation endpoints, with link connections strictly matching the interface definitions of connected subcomponents after interface refinement is completed.

No explicit timing-related properties shall be configured for any system, device component or their instances in the current baseline version, including but not limited to periodic scheduling rules, execution priority attributes, end-to-end transmission latency constraints, component worst-case execution time budgets, or hard/soft response time requirements. Reserved configuration entry points shall be retained for all timing-related attributes. Subsequent timing constraint binding shall be applied to specific subcomponent instances and interaction links, and shall not violate the flat scheduling domain partition of the single-tier deployment configuration. Timing configurations for software and hardware components within the ControlSystem domain shall align with the inherent property requirements of the referenced external components from the SoftwareParts and PhysicalParts packages to avoid integration mismatch.

No custom data type definitions shall be created within the IntegratedSCS package in the current baseline version. All data types used for subsequent interface interaction and data transmission shall reuse compliant data types already defined in the dependent SoftwareParts and PhysicalParts packages, and duplicate definitions of existing external data structures within the IntegratedSCS package are prohibited. No custom communication bus definitions, including both physical hardware interconnection buses and logical software communication channels, shall be created within the IntegratedSCS package in the current baseline version. All communication links between field devices and system instances, as well as between internal software and hardware subcomponents of the ControlSystem, shall reuse physical bus definitions provided by the PhysicalParts package and software communication middleware abstractions provided by the SoftwareParts package in subsequent configuration. Bus access rules shall match the physical and logical characteristics of the interfaces of connected subcomponents after interface refinement to ensure compatible interconnection.
