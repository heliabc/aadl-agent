A public AADL package named thermostat shall be defined to encapsulate all modeling elements associated with the thermostat system. This package shall declare an explicit import dependency on the external data package isoletteDataModel, and no additional cross-package dependencies shall be included. The package shall contain one top-level system component type designated thermostat_ss, which represents the core thermostat subsystem. A single concrete system implementation identified as thermostat_ss.impl shall be provided for the thermostat_ss component type. This implementation shall contain no nested internal subcomponents, internal connection declarations, or resource binding statements in its current baseline.

The thermostat_ss system type shall expose four external data port interfaces, comprising two unidirectional input data ports and two unidirectional output data ports. The first input port shall be named current_temperature, configured with an in direction, and shall transport data values conforming to the isoletteDataModel::current_temperature data type to receive real-time current temperature measurements from external sensing components. The second input port shall be named operator_settings, configured with an in direction, and shall transport data values conforming to the isoletteDataModel::operator_settings data type to receive configuration parameters submitted by system operators. The first output port shall be named heat_control, configured with an out direction, and shall transport data values conforming to the isoletteDataModel::heat_control data type to send actuation commands to external heating control hardware. The second output port shall be named operator_feedback, configured with an out direction, and shall transport data values conforming to the isoletteDataModel::operator_feedback data type to deliver operational status information to the operator-facing interface. The thermostat_ss.impl system implementation shall not define internal private ports, subcomponent-level interfaces, or internal cross-component connection constructs in the current baseline.

The thermostat_ss system type shall declare one formal end-to-end flow path named current_temperature_flow. This flow path shall specify a contiguous data propagation route that originates at the current_temperature input port as the source endpoint and terminates at the heat_control output port as the sink endpoint, representing the core functional data path from incoming temperature sensing input to outgoing heating actuation output. No additional end-to-end flow paths covering the remaining external ports shall be specified in the current model version, and the declared flow path shall not define intermediate internal processing hops, as no internal subcomponents are present in the associated implementation.

No explicit component scheduling policies, periodic or aperiodic triggering rules, port communication latency values, end-to-end flow latency constraints, thread execution time budgets, or deadline requirements shall be defined within the current thermostat package model. All timing, scheduling, and latency related specifications shall be reserved for subsequent model refinement and implementation expansion.

All data types utilized for inter-component communication across system ports shall be defined within the externally imported isoletteDataModel package. No native custom data type definitions shall be contained within the thermostat package itself. All external interaction points of the thermostat system shall use sampled data ports as the sole communication abstraction, with no event ports, event-data ports, subprogram access points, or bus access features declared as part of the system’s external interface. No logical or physical communication bus definitions, bus access interfaces, or port-to-bus binding rules shall be declared within the thermostat package in the current baseline. All bus architecture and communication medium specifications shall be reserved for subsequent model extension.
