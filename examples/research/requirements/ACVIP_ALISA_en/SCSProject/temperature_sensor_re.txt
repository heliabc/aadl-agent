The system shall define a public AADL package named temperature_sensor to contain all structural modeling elements associated with temperature sensor functionality. This package shall establish an explicit import dependency on the external isoletteDataModel package to access pre-defined shared data type specifications, and shall not include nested sub-packages, undeclared external dependencies, or encapsulated elements unrelated to temperature sensor representation.

The temperature_sensor package shall declare a device component type named temperature_sensor_dev to serve as the formal abstraction of the physical temperature sensing hardware. This device component type shall expose a single external interface feature in the form of an outgoing data port identified as current_temperature. The component type shall be paired with a concrete device implementation named temperature_sensor_dev.impl, which shall not define internal subcomponents, private functional features, internal interaction ports, or internal connection pathways. No internal interfaces shall be exposed by the implementation that are not specified at the component type level.

The current_temperature output port defined on the temperature_sensor_dev component shall strictly adhere to the data structure of the current_temperature type imported from the isoletteDataModel package, with no alteration to port direction, data type reference, or port identifier permitted in the associated implementation.

The temperature_sensor_dev component type shall specify a named flow source called current_temperature_flow, which takes the component’s current_temperature output port as its originating point. This flow specification defines the complete internal data path for temperature measurements generated by the sensor, with no internal flow segments, branching routes, intermediate processing stages, or incoming data flow paths contained within the device boundary. All sensed temperature data produced by the device shall be transmitted externally exclusively through the current_temperature output port, which acts as the sole data egress point for the sensor component.

No mandatory timing, scheduling, or latency constraints shall be defined for the temperature_sensor_dev component or its impl implementation within the package scope. This includes, but is not limited to, periodic execution schedules, execution deadline thresholds, port transmission latency limits, worst-case response time requirements, and execution priority assignments. Timing-related properties for the sensor device may be added during subsequent higher-level system integration without modifying the core structural definition of the component.

All data conveyed through the current_temperature output port shall utilize the shared current_temperature data type defined in the imported isoletteDataModel package, and no local, duplicate, or modified definition of this temperature data type shall be created within the temperature_sensor package. No dedicated communication bus definitions, bus access features, or static port-to-bus binding rules shall be declared within the temperature_sensor package. The current_temperature output port shall not be pre-associated with any specific physical or logical communication bus, leaving bus binding configuration to be completed during system-level deployment modeling per integration requirements.
