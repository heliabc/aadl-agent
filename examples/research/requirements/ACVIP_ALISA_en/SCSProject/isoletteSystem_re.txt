The top-level modeling package shall be named isoletteSystem, with public access scope and explicit import dependencies on four external packages: thermostat, heat_source, temperature_sensor, and operator_interface. A top-level system component type designated isoletteSystem shall be defined within the package to act as the root encapsulation container for all isolette system elements, with no externally accessible ports declared at this top system type boundary. A system implementation identified as isoletteSystem.impl shall be specified as the first-tier integration realization of the top-level system, hosting four directly contained subcomponents. The first subcomponent shall be named thermostat, classified as a system component that references the thermostat_ss.impl implementation from the thermostat package, to deliver core closed-loop temperature regulation functionality. The second subcomponent shall be named temperature_sensor, classified as a device component that references the temperature_sensor_dev.impl implementation from the temperature_sensor package, to perform continuous ambient temperature measurement and sampling. The third subcomponent shall be named heat_source, classified as a device component that references the heat_source_dev.impl implementation from the heat_source package, to produce adjustable heat output in response to received control commands. The fourth subcomponent shall be named operator_interface, classified as a system component that references the operator_interface_ss.impl implementation from the operator_interface package, to handle operator configuration input and system status presentation.

All inter-component interaction interfaces shall take the form of directional data ports, with port contracts fully inherited from the referenced external component implementations to avoid redundant interface definition at the top integration level. The temperature_sensor device subcomponent shall provide an output data port named current_temperature for transmission of sampled real-time temperature measurements. The thermostat subcomponent shall expose four directional data ports: an input data port named current_temperature for reception of sampled temperature data from the sensing device, an input data port named operator_settings for reception of configuration parameters from the operator interface, an output data port named heat_control for transmission of heating adjustment commands to the heat source device, and an output data port named operator_feedback for transmission of operational status data to the operator interface. The heat_source device subcomponent shall provide an input data port named heat_control for reception of heating control commands from the thermostat. The operator_interface subcomponent shall expose two directional data ports: an output data port named operator_settings for transmission of user-entered configuration parameters, and an input data port named operator_feedback for reception of system status feedback from the thermostat. No additional ports shall be added to subcomponents within the top-level system implementation.

Four point-to-point port connections shall be instantiated between matching subcomponent ports to enable unobstructed inter-component data transfer. The first connection, named current_temperature, shall connect the current_temperature output port of the temperature_sensor subcomponent to the current_temperature input port of the thermostat subcomponent, carrying continuous real-time temperature sampling data. The second connection, named heat_control, shall connect the heat_control output port of the thermostat subcomponent to the heat_control input port of the heat_source subcomponent, carrying heating actuation commands. The third connection, named operator_settings, shall connect the operator_settings output port of the operator_interface subcomponent to the operator_settings input port of the thermostat subcomponent, carrying user-configured operating parameters. The fourth connection, named operator_feedback, shall connect the operator_feedback output port of the thermostat subcomponent to the operator_feedback input port of the operator_interface subcomponent, carrying system operational status data for operator display. An end-to-end flow path designated path1 shall be declared to represent the core closed-loop temperature control data pathway, originating at the internal current_temperature_flow flow source within the temperature_sensor subcomponent, passing sequentially through the current_temperature inter-component port connection, the internal current_temperature_flow processing segment within the thermostat subcomponent, and the heat_control inter-component port connection, before terminating at the internal heat_control_flow flow sink within the heat_source subcomponent.

Deterministic latency constraints shall be assigned to each inter-component port connection and the defined end-to-end flow path to meet real-time system performance requirements. The current_temperature connection between the temperature_sensor and thermostat shall enforce an allowed one-way transmission latency range of 2 milliseconds to 4 milliseconds. The heat_control connection between the thermostat and heat_source shall enforce an allowed one-way transmission latency range of 5 milliseconds to 6 milliseconds. The operator_settings connection between the operator_interface and thermostat shall enforce an allowed one-way transmission latency range of 1 millisecond to 2 milliseconds. The operator_feedback connection between the thermostat and operator_interface shall enforce an allowed one-way transmission latency range of 2 milliseconds to 4 milliseconds. The end-to-end flow path path1, spanning the full operational chain from initial temperature sampling to delivery of heating commands to the actuation device, shall enforce a cumulative end-to-end latency range of 5 milliseconds to 9 milliseconds, with this bound covering all data transmission delays across inter-component links and internal processing delays within traversed subcomponents.

No custom data type definitions shall be declared within the isoletteSystem package. All data payloads exchanged across inter-component ports shall adhere strictly to the data type specifications defined for corresponding ports in the referenced external dependent packages, with no redundant type redefinition or override at the top system integration level. No dedicated shared bus components shall be defined within the isoletteSystem package to mediate inter-component communication. All inter-component data transfer shall be implemented via direct point-to-point port connections, with communication quality attributes including latency bound directly to individual port connection instances, with no intermediate bus abstraction layer inserted between communicating components.
