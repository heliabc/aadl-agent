The system shall establish a standalone publicly accessible AADL package named DataModel, which functions as the centralized reusable data type definition repository for the overall system model. This package maintains no import dependencies on any other external AADL packages, and all model elements declared within the public section of the package are available for reference and use by other packages in the system model that declare appropriate public access to the DataModel package. The DataModel package is scoped exclusively to hold data type definitions, and does not encapsulate system, hardware, software, or execution platform component declarations within its boundary.

No component type or component implementation declarations are included in the DataModel package, so there are no requirements for definition of external functional interfaces, internal interaction points, port declarations, subprogram access points, or component-level access contracts within the scope of this package. No component hierarchy, subcomponent composition, or component connection structure is defined as part of this package’s content.

As the DataModel package contains only static data type specifications without executable component instances, communication links, or port connection declarations, there are no defined end-to-end data transmission paths, segment-level data flow routes, or data routing rules specified within this package. All data flow definitions that use the data types declared in this package shall be specified in separate system or component implementation packages that import the DataModel repository.

The DataModel package does not contain declarations for threads, processes, processors, virtual processors, schedulers, or other execution-related model elements, so no periodic dispatch rules, execution deadline constraints, end-to-end latency budgets, transmission delay limits, or jitter tolerance requirements are defined within the scope of this package. All timing and scheduling constraints associated with data instances of the types defined in this package shall be specified in the relevant execution and component architecture packages that reference these data types.

Two core reusable data types shall be defined within the public section of the DataModel package, with no associated data implementation declarations provided for either type, as they serve as standardized payload type specifications rather than composite data structures requiring internal subcomponent composition. The first data type is named SensorData, which represents structured sampled sensor measurement data exchanged between system sensing and processing elements; this data type shall have a fixed Data_Size property value of 2 KByte to standardize static memory allocation, transmission payload calculation, and buffer sizing for all usages of SensorData across the system model. The second data type is named actuatecmd, which represents structured actuation command data transmitted between system control processing elements and actuation output elements; this data type shall have a fixed Data_Size property value of 100 Bytes to standardize static memory allocation, transmission payload calculation, and buffer sizing for all usages of actuatecmd across the system model. No communication bus, virtual bus, bus access protocol, or bus-related property definitions are included in the DataModel package, as bus specification falls outside the scope of this dedicated data type repository.
