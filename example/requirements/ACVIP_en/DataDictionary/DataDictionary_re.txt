The system shall define a standalone public AADL package named DataDictionary that operates as the centralized shared data type repository for the full system model. This package shall not declare dependencies on any other custom component packages, domain-specific model libraries, or user-defined property sets, and shall only reference the AADL standard predefined core property set to support configuration of built-in data attributes. All type definitions contained in the DataDictionary package shall have public visibility, allowing unconstrained reference by all other packages and components across the system model to ensure consistent data typing for cross-component interactions.

The DataDictionary package shall contain two data component type definitions, designated SensorData and BrakeSignal respectively. Neither data component shall declare external interaction interfaces, including required or provided data ports, event ports, event data ports, subprogram access points, or bus access interfaces. Neither data component shall define internal subcomponent hierarchies, internal connection logic, or separate implementation artifacts, as both components serve exclusively as typed data carriers for cross-component data exchange rather than executable functional entities.

The DataDictionary package shall not define executable functional components, hardware devices, communication links, or component interconnection bindings, and as such shall not specify end-to-end data flow paths, data routing rules, or in-line data processing sequences. All data flow interactions that leverage the data types defined in this package shall be specified within the corresponding application or platform packages that host the connected functional components, with no data forwarding, transformation, or routing logic encapsulated within the DataDictionary package.

The DataDictionary package shall not contain any schedulable execution entities, including threads, thread groups, processes, virtual processors, or physical processors, and thus shall not define scheduling policies, execution periods, dispatch protocols, hard or soft deadline constraints, allowable jitter limits, or end-to-end latency requirements. All timing and scheduling attributes for components that reference data types from this package shall be configured within the defining scope of the respective component’s parent package, with no timing-related constraints applied to the static data type definitions held in the DataDictionary package.

Each data type defined in the DataDictionary package shall be assigned a fixed Data_Size property to guarantee consistent serialization length across all communication transmission and persistent storage scenarios. The SensorData data type shall be configured with a Data_Size property value of 8 bytes. The BrakeSignal data type shall be configured with a Data_Size property value of 8 bytes. The DataDictionary package shall not define communication bus types, bus implementations, bus access protocols, or bus property constraints, as all communication medium definitions shall be captured in dedicated platform architecture packages separated from the shared data type repository.
