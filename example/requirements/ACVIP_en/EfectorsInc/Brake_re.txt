The system shall define a top-level public AADL package named Brake, which shall explicitly declare import dependencies on three pre-existing external packages: the DataDictionary package containing shared system data type definitions, the Infrastructure package containing pre-modeled communication and power bus definitions, and the SEI package containing standard reusable non-functional property definitions. The Brake package shall contain all component definitions related to the brake actuator unit, with no nested sub-packages declared within its scope. Within the Brake package, a device component type named SimpleBrake shall be defined to represent the basic hardware brake actuator, and a corresponding device implementation named SimpleBrake.i shall be defined to specify the concrete property values and implementation characteristics of the SimpleBrake device type.

The SimpleBrake device type shall expose three external features as its complete external interface, with no additional provided or required interfaces defined on the component type. The first feature is a data input port named dataIn, configured as an in-direction data port for reception of incoming brake signal data. The second feature is a required bus access port named busIn, which declares the device’s need to access a specified communication bus instance. The third feature is a required bus access port named powerIn, which declares the device’s need to access a specified power supply bus instance. The SimpleBrake.i device implementation shall not define any internal subcomponents, internal connection paths, call sequences, or private internal interfaces, and shall realize the device functionality as a self-contained hardware unit interacting with external elements solely through the three external features defined on the SimpleBrake device type.

The SimpleBrake device shall define a dedicated sink flow path named brakeFlow, which takes the dataIn input port as its sole ingress point and terminates within the device’s internal actuation logic. No egress segment shall be defined for the brakeFlow path, as the path represents a unidirectional flow of brake command data into the device for actuation processing. The device shall process incoming brake signal data received via the dataIn port to execute physical brake actuation actions aligned with the received signal value.

The brakeFlow end-to-end path within the SimpleBrake.i implementation shall satisfy a bounded latency constraint, with the total propagation delay from the point a valid brake signal arrives at the dataIn port to the point the device completes the corresponding actuation action for that signal falling within the closed range of 3 milliseconds to 5 milliseconds. No periodic dispatch or time-triggered scheduling configuration shall be defined for the SimpleBrake device, as the unit operates as a hardware actuator that responds directly to valid input signals received at its dataIn port. The SimpleBrake.i implementation shall comply with defined non-functional resource constraints, including a total device weight limit of 1.0 kilograms applied to the entire device assembly, and a power consumption budget of 4.0 watts applied specifically to the powerIn bus access interface, such that the maximum power the device draws through the powerIn port during normal operation shall not exceed the 4.0 watt budget.

All data transmitted through the dataIn input port shall strictly conform to the BrakeSignal data type defined in the imported DataDictionary package, with no alternative or custom data types permitted for brake signal transmission on this port. The busIn required access port shall only connect to the i instance of the canBus controller area network bus defined in the imported Infrastructure package, representing the device’s required access to the specified CAN bus instance. The powerIn required access port shall only connect to the generic instance of the power supply bus defined in the imported Infrastructure package, through which the device draws all required operating power. All non-functional property assignments for weight limit and power budget shall reference the standard property definitions contained in the imported SEI package, with the WeightLimit property applied to the full scope of the SimpleBrake.i implementation and the powerBudget property applied exclusively to the powerIn bus access port.
