The top-level software and hardware package for the wheel brake system shall be defined under the namespace impl::wbs, with public access to all contained elements, and shall declare explicit import dependencies on seven external supporting packages: impl::bscu for brake system control unit components, impl::communication for annunciation device components, impl::valves for all hydraulic valve assembly components, impl::wheel for wheel brake assembly components, impl::pump for hydraulic pump components, impl::power for electrical power supply components, and impl::pedals for pilot brake pedal input components. No private package sections shall be defined for the impl::wbs package. An abstract system type named wbs shall be defined as the root type for all wheel brake system variants, with no inherent features, properties, or subcomponents declared at the type level to support flexible extension across implementation variants. Four concrete system implementations shall be defined under the wbs system type, following a hierarchical extension structure where wbs.generic serves as the common base implementation for all variants, wbs.basic and wbs.detailed directly extend wbs.generic to implement simplified and high-fidelity hydraulic architectures respectively, and wbs.federated and wbs.ima directly extend wbs.detailed to implement federated and integrated modular avionics deployment architectures for the brake system control unit. The base wbs.generic implementation shall define a fixed set of subcomponents retained across all extending variants, including a pedal input subsystem typed as impl::pedals::pedals.generic, an electrical power subsystem typed as impl::power::power.generic, two primary hydraulic pump systems typed as impl::pump::pump.i designated blue_pump and green_pump for the two independent hydraulic supply circuits, an accumulator backup pump system typed as impl::pump::pump.i designated accumulator for emergency pressure supply, an abstract selector valve assembly typed as impl::valves::selector, a generic brake system control unit typed as impl::bscu::bscu.generic designated bscu, an abstract wheel brake assembly typed as impl::wheel::wheel, and a fault annunciation device typed as impl::communication::annunciation.i designated annunciation. The wbs.basic implementation shall apply type extension substitution rules to refine three inherited subcomponents from the base generic implementation, replacing the generic bscu with the basic BSCU variant impl::bscu::bscu.basic, replacing the abstract selector with the simplified selector assembly impl::valves::selector_basic, and replacing the abstract wheel assembly with the single-input wheel variant impl::wheel::wheel_one_input.i, with no additional subcomponents added beyond the refined inherited elements. The wbs.detailed implementation shall apply type extension substitution rules to refine two inherited subcomponents from the base generic implementation, replacing the abstract selector with the high-fidelity detailed selector assembly impl::valves::selector_detailed, and replacing the abstract wheel assembly with the dual-input wheel variant impl::wheel::wheel_two_inputs.i, and shall add three new hydraulic valve subcomponents not present in the base implementation: a boolean-actuated shutoff valve typed as impl::valves::boolean_shutoff designated shutoff for gating the green hydraulic circuit supply, and two command-actuated shutoff valves typed as impl::valves::cmd_shutoff designated green_skid and blue_skid to provide anti-skid modulation for the green and blue hydraulic circuits respectively. The wbs.federated implementation shall inherit all subcomponents and structural elements from wbs.detailed, with a single type refinement to replace the inherited BSCU subcomponent with the federated BSCU variant impl::bscu::bscu.federated, applying valid type extension rules to maintain interface compatibility. The wbs.ima implementation shall inherit all subcomponents and structural elements from wbs.detailed, with a single type refinement to replace the inherited BSCU subcomponent with the integrated modular avionics BSCU variant impl::bscu::bscu.ima, applying valid type extension rules to maintain interface compatibility.

All contained components shall define consistent, extension-compatible interfaces to support substitution across implementation variants without breaking inherited connections. The pedal input subsystem shall expose two unidirectional discrete output ports designated signal1 and signal2, carrying redundant pilot brake pedal position input values. The electrical power subsystem shall expose two provided bus access points designated line1 and line2, delivering independent, redundant electrical power supply feeds. All pump components, including the blue primary pump, green primary pump, and accumulator backup pump, shall expose a single provided bus access point designated pressure_output, delivering pressurized hydraulic fluid supply to connected hydraulic components. The abstract base selector valve assembly shall expose a single required bus access point designated accumulator_input for receiving backup pressure from the accumulator pump. The simplified selector_basic variant used in the basic implementation shall extend the base selector interface to add two required bus access points designated blue_input and green_input for receiving pressure from the blue and green primary pumps, three unidirectional input ports designated Select_Alternate, cmd_nor, and cmd_alt for receiving circuit selection and brake command signals from the BSCU, and a single provided bus access point designated output for delivering regulated brake pressure to the wheel assembly. The high-fidelity selector_detailed variant used in the detailed, federated, and IMA implementations shall extend the base selector interface to add two required bus access points designated blue_input and green_input for receiving pressure from the blue primary pump and gated green supply path respectively, a unidirectional input port designated select_alternate for receiving circuit selection commands from the BSCU, and two provided bus access points designated green_output and blue_output for delivering regulated pressure to the green and blue anti-skid valves respectively. The boolean-actuated shutoff valve used in detailed architecture variants shall expose a required bus access point designated input for receiving incoming hydraulic pressure from the green pump, a provided bus access point designated output for delivering gated pressure to the selector green input, and a unidirectional boolean input port designated boolean_input for receiving open/close actuation commands from the BSCU. Each command-actuated anti-skid shutoff valve shall expose a required bus access point designated input for receiving regulated pressure from the selector assembly, a provided bus access point designated output for delivering modulated brake pressure to the wheel assembly, and a unidirectional command input port designated cmd_input for receiving anti-skid modulation commands from the BSCU. The abstract base wheel brake assembly shall define a common root type for wheel variants, with no concrete interface features declared at the abstract level. The single-input wheel_one_input.i variant used in the basic implementation shall extend the base wheel type to expose a single required bus access point designated input for receiving consolidated brake pressure supply from the simplified selector. The dual-input wheel_two_inputs.i variant used in detailed, federated, and IMA implementations shall extend the base wheel type to expose two required bus access points designated blue_input and green_input for receiving modulated pressure from the blue and green anti-skid valves respectively. All BSCU variants, including the generic, basic, federated, and IMA types, shall expose a consistent core interface to maintain cross-variant compatibility, including two unidirectional input ports designated pedal1 and pedal2 for receiving redundant pedal position signals from the pedal subsystem, two required bus access points designated pwr1 and pwr2 for connecting to the redundant power supply feeds from the power subsystem, a unidirectional output port designated Select_Alternate for transmitting hydraulic circuit selection commands, and two unidirectional output ports designated cmd_nor and cmd_alt for transmitting normal and alternate brake modulation commands to connected valve components. The annunciation device shall expose a state propagation interface supporting error state reporting, with two discrete component states representing fully operational functionality and failed functionality, to support system-level fault state evaluation and pilot annunciation of brake system failures.

All system connections shall be defined at the implementation level, with a core set of connections retained across all variants, and additional connections added or refined to support the architecture of each implementation variant. The core connections defined in the base wbs.generic implementation, inherited by all extending variants, include a bidirectional bus access connection between the accumulator pump pressure output and the selector accumulator input to deliver backup hydraulic pressure, bidirectional bus access connections between the power subsystem line1 and BSCU pwr1 interface and between the power subsystem line2 and BSCU pwr2 interface to deliver redundant electrical power to the BSCU, and unidirectional port connections from the pedals signal1 output to the BSCU pedal1 input and from the pedals signal2 output to the BSCU pedal2 input to deliver pilot brake input signals. The wbs.basic implementation shall add connections to support the simplified single-path hydraulic architecture, including bidirectional bus access connections between the blue pump pressure output and the simplified selector blue input, and between the green pump pressure output and the simplified selector green input to deliver primary pump pressure to the selector, unidirectional port connections from the BSCU Select_Alternate output to the simplified selector Select_Alternate input, from the BSCU cmd_nor output to the simplified selector cmd_nor input, and from the BSCU cmd_alt output to the simplified selector cmd_alt input to deliver BSCU control commands to the selector, and a bidirectional bus access connection between the simplified selector output and the single-input wheel input to deliver consolidated regulated brake pressure to the wheel brake assembly. The wbs.detailed implementation and its extending federated and IMA variants shall add connections to support the split dual-path hydraulic architecture with independent anti-skid modulation, including a bidirectional bus access connection between the blue pump pressure output and the detailed selector blue input to deliver direct blue circuit pressure to the selector, a bidirectional bus access connection between the green pump pressure output and the boolean shutoff valve input to route green circuit pressure through the shutoff valve, a bidirectional bus access connection between the shutoff valve output and the detailed selector green input to deliver gated green circuit pressure to the selector, unidirectional port connections from the BSCU Select_Alternate output to both the shutoff valve boolean input and the detailed selector select_alternate input to coordinate green circuit activation during alternate mode operation, unidirectional port connections from the BSCU cmd_nor output to the green_skid valve cmd_input and from the BSCU cmd_alt output to the blue_skid valve cmd_input to deliver independent anti-skid modulation commands to each circuit, bidirectional bus access connections between the detailed selector green output and the green_skid valve input and between the detailed selector blue output and the blue_skid valve input to deliver regulated circuit pressure to the anti-skid valves, and bidirectional bus access connections between the blue_skid valve output and the wheel blue_input and between the green_skid valve output and the wheel green_input to deliver modulated brake pressure from each independent circuit to the dual-input wheel brake assembly. The wbs.federated and wbs.ima implementations shall retain all connections defined in wbs.detailed, with no additional connection modifications required due to the interface-compatible BSCU refinement applied in these variants.

No explicit thread-level scheduling or end-to-end latency constraints shall be defined for the base wbs.generic, wbs.basic, or wbs.detailed implementations, as these variants use abstract or non-deployment-specific BSCU types that do not bind functions to specific computing resources. The wbs.federated implementation, which uses a federated BSCU variant, shall enforce dedicated resource scheduling for BSCU functions, where brake control and anti-skid logic execute on independent, dedicated computing modules with separate scheduling domains, eliminating resource contention between BSCU functions and other aircraft systems. The wbs.ima implementation, which uses an integrated modular avionics BSCU variant, shall enforce time-partitioned scheduling for BSCU functions executing on shared avionics computing resources, adhering to strict time partition allocation rules to prevent cross-function interference and guarantee deterministic execution of brake control logic. All hardwired signal and hydraulic bus connections shall propagate signals and pressure with negligible latency consistent with physical hardware behavior, with no scheduled transmission delays introduced by communication protocol stacks. System-level composite error behavior shall be evaluated continuously during system operation to detect fault conditions, with error state propagation occurring instantaneously across connected components to support timely fault detection and annunciation. The system shall support six defined top-level error states as specified in the error model: Operational, representing fully functional brake system performance, AnnunciatedTotalBrakingLoss representing total loss of brake function with active pilot fault annunciation, UnannunciatedTotalBrakingLoss representing total loss of brake function without active pilot fault annunciation, PartialBrakingLoss representing reduced brake function across one or more hydraulic circuits, AsymmetricLoss representing unequal brake force application across wheel brakes leading to directional control issues, and InadvertentBrake representing uncommanded brake application in the absence of pilot input. The composite error behavior logic shall define explicit transitions for total brake loss failure states as follows: an unannunciated total wheel brake loss failure state shall be entered when the BSCU is in a failed state, the accumulator pump is in a failed state, and the annunciation device is in a failed state, or when both the blue and green primary pumps are in failed states, the accumulator pump is in a failed state, and the annunciation device is in a failed state, with the duplicate trigger condition for combined BSCU and accumulator failure with annunciation failure retained as specified in the error model. An annunciated total wheel brake loss failure state shall be entered when the BSCU is in a failed state, the accumulator pump is in a failed state, and the annunciation device is in an operational state, or when both the blue and green primary pumps are in failed states, the accumulator pump is in a failed state, and the annunciation device is in an operational state, with the duplicate trigger condition for combined BSCU and accumulator failure with operational annunciation retained as specified in the error model. Transitions for partial braking loss, asymmetric loss, and inadvertent brake states shall be supported by the imported error library for subsequent implementation refinement.

All communication between system components shall use two distinct connection types, each with defined data and transmission rules. Hydraulic pressure transfer connections between pumps, valves, selectors, and wheel assemblies shall be implemented as bidirectional bus access connections, representing physical hydraulic fluid flow rather than digital data transfer, with continuous analog pressure values passed between connected components, no packetization, no addressing, and no protocol overhead. Electrical power transfer connections between the power subsystem and BSCU shall be implemented as bidirectional bus access connections, representing continuous electrical power delivery, with no data payload carried over the power connections, and redundant feeds maintained as independent, electrically isolated buses to prevent common-cause failure. Control signal connections between pedals, BSCU, and valve components shall be implemented as unidirectional port connections, carrying discrete or analog data values including pedal position measurements, boolean valve actuation commands, circuit selection signals, and brake modulation commands, with direct point-to-point transmission, no bus arbitration, and no protocol encapsulation consistent with hardwired avionics signal connections. Error state propagation between components shall use the EMV2 error modeling annex, with error types imported from the dedicated WBSImplementationErrorLib error library, and component-level error behavior defined using the TwostateWBS behavior specification from the same library, which defines two mutually exclusive component states for all fault-monitored components: Operational, representing fully functional component behavior, and Failed, representing total loss of component function. All component type substitutions across implementation variants shall follow the Type_Extension classifier substitution rule, ensuring that substituted components are valid subtypes of the original component type and fully implement the required interface of the original component to maintain connection compatibility across variants. No custom data types, bus types, device types, or system types shall be defined within the impl::wbs package beyond the root wbs system type and its implementations, as all port, bus, and subcomponent interfaces rely on types and components defined in the imported supporting packages.
