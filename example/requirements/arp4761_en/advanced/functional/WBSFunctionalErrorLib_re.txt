A public AADL package named WBSFunctionalErrorLib shall be defined to act as a centralized, reusable repository for wheel brake system functional-level error modeling constructs. The package shall declare a formal dependency on the external error definition library WBSImplementationErrorLib to support cross-layer error type alias mapping between functional and implementation error domains. The package shall integrate the EMV2 modeling annex to host standardized hierarchical error type definitions and reusable error behavior state machine templates. No instantiable components of any category, including hardware, software, process, thread, device, or system components, shall be defined within the package, and no nested sub-packages shall be included. All constructs stored in the package shall be marked with public accessibility to support reference by all WBS-related components across the full system model hierarchy.

The WBSFunctionalErrorLib package operates as a static design-time modeling definition library, and shall not define any input or output ports for runtime data or control interaction. No internal subcomponents shall be declared within the package structure, so no internal inter-component interface contracts, port matching rules, or connection specifications are required. The only externally exposed elements of the package are referenceable error type entities and error behavior templates, with no mandatory port-level interaction obligations for model elements that import and apply the library constructs.

As a static repository of design-time modeling constructs, the package shall not participate in any runtime data exchange activities. No runtime data flow paths for data production, forwarding, aggregation, or consumption shall be defined within the package, and no end-to-end data transmission logic across components, ports, or execution boundaries shall be associated with any element contained in the library.

All constructs within the WBSFunctionalErrorLib package are static design-time modeling elements with no runtime execution footprint, and shall not be bound to any runtime schedulable entities such as threads, processes, virtual processors, or partition execution contexts. No timing constraints including execution period, deadline, end-to-end latency, scheduling priority, or execution time budgets shall be specified for any element within the package.

All error type definitions within the package shall follow a strict hierarchical inheritance structure aligned with EMV2 specification rules. A root abstract error type named AnyFunctionalError shall be defined as the ultimate parent type for all WBS functional error categories. An alias error type named AliasAnyFunctionalError shall be defined to directly rename the AnyImplementationError type from the WBSImplementationErrorLib package, to establish consistent type mapping and propagation between the functional error layer and implementation error layer. Three standalone hydraulic-related error types shall be defined at the top level of the error type hierarchy: HydraulicLossBlue to represent pressure loss in the blue hydraulic supply circuit, HydraulicLossGreen to represent pressure loss in the green hydraulic supply circuit, and HydraulicLossComponents to represent functional loss of individual hydraulic system components. The NoService error type shall be defined as a direct subtype of AnyFunctionalError to represent total loss of expected component service, with two further concrete subtypes derived from NoService: NoValue to represent loss of valid output data or signal value, and NoPower to represent loss of input power supply to a component. The TotalWBLoss error type shall be defined as a direct subtype of AnyFunctionalError to represent complete loss of wheel brake function, with two further concrete subtypes derived from TotalWBLoss: TotalWBLossAnunciated to represent total brake loss that is properly detected and annunciated to the crew, and TotalWBLossUnanunciated to represent total brake loss that is not detected or annunciated. The PartialSymmetricalWBLoss error type shall be defined as a direct subtype of AnyFunctionalError to represent symmetrical, equal magnitude partial loss of brake function across left and right brake channels, with two further concrete subtypes derived from PartialSymmetricalWBLoss: PartialSymmetricalWBLossAnunciated to represent symmetrical partial brake loss that is properly detected and annunciated, and PartialSymmetricalWBLossUnanunciated to represent symmetrical partial brake loss that is not detected or annunciated. The AssymetricalWBLoss error type shall be defined as a direct subtype of AnyFunctionalError to represent unequal, asymmetrical brake function loss across left and right brake channels. The InadvertentWB error type shall be defined as a direct subtype of AnyFunctionalError to represent uncommanded, unintended activation of wheel brake function without valid pilot or system input. Two fixed error set types shall be defined for aggregated error reference across the model: the WBErrorSet type shall form a fixed enumeration of error types including TotalWBLossAnunciated, TotalWBLossUnanunciated, PartialSymmetricalWBLoss, AssymetricalWBLoss, and InadvertentWB, for use in general dual-state error behavior state associations; the HydraulicErrors type shall form a fixed enumeration of error types including HydraulicLossBlue, HydraulicLossGreen, HydraulicLossComponents, and NoService, for use in hydraulic subsystem fault propagation and aggregation logic. Two reusable error behavior state machine templates shall be defined within the EMV2 annex. The first template, named Twostate, shall import all error types from the local WBSFunctionalErrorLib namespace, define Operational as the initial normal operating state, and define a failed error state associated with the full set of errors covered by the WBErrorSet type. The second template, named TwostateWBS, shall be dedicated to top-level WBS component error behavior modeling, import all error types from the local WBSFunctionalErrorLib namespace, define Operational as the initial normal operating state, and define a failed error state that explicitly enumerates all concrete WBS error subtypes that must be traceable via error containment paths, including TotalWBLossAnunciated, TotalWBLossUnanunciated, PartialSymmetricalWBLossUnanunciated, PartialSymmetricalWBLossAnunciated, AssymetricalWBLoss, and InadvertentWB. Implicit coverage of these concrete subtypes via parent error type references or error set references shall not be used for the TwostateWBS failed state definition, to ensure unambiguous reference and traceability of error propagation paths across the model containment hierarchy. No bus, virtual bus, or bus access interface types shall be defined within the package, and no bus-related protocol, bandwidth, transmission latency, arbitration, or access control rules shall be specified as part of the library constructs.
