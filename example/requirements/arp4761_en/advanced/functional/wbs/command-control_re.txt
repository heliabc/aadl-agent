A public AADL package identified by the path functional::WheelBrake::CommandControl shall be constructed to encapsulate all model elements associated with the wheel brake system command control function. This package shall establish explicit import dependencies on four external packages to satisfy model construction requirements: the functional::GenericFunctions package, which supplies reusable, general-purpose function component definitions; the WBSPS package, which supplies wheel brake system-specific property sets and functional error type definitions; the EMV2 package, which supplies standardized error modeling annex syntax, rules, and semantic definitions; and the functional::WheelBrake::Generic package, which supplies abstract base system types and base implementation definitions common to all wheel brake domain function components. The top-level system type defined within this package shall carry the identifier CommandControl, and shall inherit all core characteristics from the GenericFunction system type hosted in the functional::WheelBrake::Generic package to ensure compliance with universal wheel brake function interface and behavior constraints. The concrete, deployable implementation of the CommandControl system shall carry the identifier CommandControl.basic, and shall inherit core implementation logic from the GenericFunction.basic implementation hosted in the functional::WheelBrake::Generic package to reuse common function capabilities. The CommandControl.basic implementation shall contain two internal subsystem subcomponents, identified as Control_Primary and Control_Secondary respectively; both subcomponents shall be instantiated directly from the Generic.basic system implementation hosted in the functional::GenericFunctions package, corresponding to the primary command processing channel and secondary command processing channel of the command control function. The CommandControl.basic implementation shall configure the WBSPS::IsFunction property to a boolean value of true to mark the component as a recognized wheel brake system functional element.

The CommandControl system type shall declare a single external feature identified as fromBSCU, which serves as the component’s only externally exposed interaction endpoint. Per defined error propagation interface rules, the fromBSCU feature shall operate as an outbound error propagation port with the capability to transmit any functional error type defined in the wheel brake functional error library. The two internal subcomponents, Control_Primary and Control_Secondary, shall fully adhere to the standard interface specifications defined for the generic Generic function component, with no additional custom internal interfaces introduced in the basic implementation variant. The command control component shall define an internal error event identified as lossBrakingCommand, which falls under the WBErrorSet error classification and corresponds to the internal fault scenario of complete braking command output loss. The component shall also support an inbound error propagation path for errors originating from the aircraft electrical system, with the capability to receive any class of functional error transmitted from upstream electrical system components.

Functional data interaction and data flow logic for the command control component shall inherit default flow rules defined in the GenericFunction base class, with no custom functional data flow paths specified in the basic implementation variant. For error flow routing, a top-level error propagation path identified as f1 shall be defined, which originates at the fromBSCU external port and propagates errors of the AnyFunctionalError classification to external connected components. When the component enters the Failed error state, all generated functional errors shall be propagated outward through the fromBSCU port per propagation rule p1, with no conditional filtering applied to the set of propagated error types. Composite error state aggregation across internal subcomponents shall follow a logical OR evaluation rule: if either the Control_Primary subcomponent or the Control_Secondary subcomponent enters the Failed error state, the top-level CommandControl component shall immediately transition to the Failed error state.

The CommandControl.basic implementation shall not define custom thread scheduling policies, execution period constraints, deadline parameters, or end-to-end latency requirements in the current variant; all applicable timing and scheduling rules shall be inherited directly from the GenericFunction.basic base implementation. The occurrence of the internal lossBrakingCommand error event shall follow a Poisson probability distribution, with a per-operational-exposure occurrence probability value of 3.3e-5, aligned with the reliability requirement specified in AIR6110 document page 49. Component error state transitions shall execute immediately upon satisfaction of defined transition guard conditions, with no intentional delay applied to error state switching logic. Two valid error state transitions shall be supported for the component: the first transition, identified as t1, shall activate when the internal lossBrakingCommand error event occurs while the component is in the Operational state, moving the component to the Failed state; the second transition, identified as t2, shall activate when any functional error is received from the electrical system propagation path while the component is in the Operational state, moving the component to the Failed state and associating the failure with the TotalWBLossUnanunciated failure effect. The component error behavior shall be based on the two-state (Twostate) error state machine imported from the WBSFunctionalErrorLib, with valid states limited to Operational and Failed.

The CommandControl.basic implementation shall not define custom AADL data types within the local package; all data types used for functional interaction shall be inherited from imported dependent packages and the GenericFunction base class. The implementation shall not define custom bus components, bus access features, or bus binding rules in the current variant; all communication bus-related configurations shall follow default specifications defined in the upper-level generic function base class. All error types referenced in the component error model shall be imported from the WBSFunctionalErrorLib error library, including the Twostate error behavior state machine definition, the AnyFunctionalError error type set, the WBErrorSet error classification, and the TotalWBLossUnanunciated failure effect type.
