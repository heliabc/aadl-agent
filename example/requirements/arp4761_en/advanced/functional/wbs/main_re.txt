The top-level public modeling package is located at the namespace path functional::WheelBrake::Main. This package declares explicit import dependencies on three external property and annex packages: WBSPS, EMV2, and ARP4761, alongside two sibling packages within the functional::WheelBrake namespace: functional::WheelBrake::Generic and functional::WheelBrake::CommandControl. The package defines three core system type hierarchies and two associated system implementation variants, structured to represent hierarchical wheel brake system functional elements. The first system type, NormalBrakeSystem, extends the GenericBrakeSystem type defined in the functional::WheelBrake::Generic package to inherit all base structural and property characteristics of a generic brake system. The second system type, DecelerateOnGround, extends the GenericFunction type defined in the functional::WheelBrake::Generic package to inherit all base structural and property characteristics of a generic system function, with one associated implementation variant labeled basic that extends the GenericFunction.basic implementation from the same Generic package. The third system type, DecelerateWheels, is defined as a standalone top-level functional system type with no parent type extension, with one associated implementation variant labeled basic. The NormalBrakeSystem element represents the normal operating mode brake function channel. The DecelerateOnGround element represents the integrated ground deceleration function that encapsulates normal, alternate, and emergency brake operating channels. The DecelerateWheels element represents the top-level wheel deceleration function that aggregates all relevant sub-functions for wheel speed management during ground operations. The DecelerateOnGround.basic implementation instantiates one NormalBrakeSystem instance to serve as the normal brake channel, alongside two instances of GenericBrakeSystem from the functional::WheelBrake::Generic package to serve as the alternate and emergency brake channels respectively. The DecelerateWheels.basic implementation instantiates one DecelerateOnGround.basic instance to serve as the ground deceleration sub-function, one CommandControl.basic instance from the functional::WheelBrake::CommandControl package to serve as the directional control sub-function, and two instances of GenericFunction.basic from the functional::WheelBrake::Generic package to serve as the main landing gear stop function and unintended motion prevention function respectively. All system types marked with the WBSPS::IsFunction property set to true are classified as functional system elements. The NormalBrakeSystem type exposes two external input features, named fromHydraulic and fromBSCU. For error propagation interfaces, NormalBrakeSystem accepts incoming error propagations on the fromHydraulic feature limited to the HydraulicErrors error set, and accepts incoming error propagations on the fromBSCU feature covering the full AnyFunctionalError error set; both features act as dedicated error sink points for their respective incoming error sets. The DecelerateOnGround type explicitly declares one external input feature named fromBSCU, and inherits the full standard input feature set from its parent GenericFunction type, including features named fromElectrical, fromHydraulic, fromAlert, fromSteering, and fromStatus. For error propagation interfaces, DecelerateOnGround accepts incoming error propagations on the fromBSCU feature covering the AnyFunctionalError error set, with the fromBSCU feature acting as an error sink point for that error set. The DecelerateOnGround.basic implementation defines internal interface mappings that connect the parent implementation’s fromBSCU input feature directly to the fromBSCU feature of the internal normal brake subcomponent. Composite error behavior for DecelerateOnGround.basic defines that the component enters a Failed state if any of its three internal subcomponents (normal, alternate, emergency) enters its own Failed state. The DecelerateWheels type exposes five external input features, named fromElectrical, fromHydraulic, fromAlert, fromSteering, and fromStatus. For error propagation interfaces, DecelerateWheels accepts incoming error propagations on each input feature aligned to defined error sets: the fromElectrical feature carries AnyFunctionalError set propagations, the fromHydraulic feature carries HydraulicErrors set propagations, the fromAlert feature carries AnyFunctionalError set propagations, the fromSteering feature carries AnyFunctionalError set propagations, and the fromStatus feature carries AnyFunctionalError set propagations. The directionalcontrol subcomponent within DecelerateWheels.basic exposes a fromBSCU feature to support internal cross-connection to the decelerateonground subcomponent, and all four internal subcomponents within DecelerateWheels.basic inherit the standard five input features (fromElectrical, fromHydraulic, fromAlert, fromSteering, fromStatus) from their respective parent function types to accept incoming signals from the parent DecelerateWheels external interfaces. All inter-component connections within the package are implemented as unidirectional point-to-point feature connections. Within the DecelerateWheels.basic implementation, each external input feature is fanned out to all four internal subcomponents via dedicated connections: the external fromElectrical input routes to the fromElectrical feature of the decelerateonground, directionalcontrol, stopmainlanding, and preventmotion subcomponents; the external fromHydraulic input routes to the fromHydraulic feature of each of the four subcomponents; the external fromAlert input routes to the fromAlert feature of each of the four subcomponents; the external fromSteering input routes to the fromSteering feature of each of the four subcomponents; the external fromStatus input routes to the fromStatus feature of each of the four subcomponents. An additional internal cross-connection routes the fromBSCU feature of the directionalcontrol subcomponent to the fromBSCU input feature of the decelerateonground subcomponent, carrying brake command outputs from the directional control function to the ground deceleration function. Within the DecelerateOnGround.basic implementation, the incoming fromBSCU signal received from the directionalcontrol subcomponent is routed directly to the fromBSCU input of the normal brake subcomponent, with no direct connections defined from parent DecelerateOnGround inputs to the alternate or emergency brake subcomponents in this basic implementation variant. Error flow and behavior logic is defined for each component via EMV2 annex specifications. The NormalBrakeSystem component initializes in the Operational state, and defines three error-triggered state transitions: a transition to the Failed state with PartialSymmetricalWBLossAnunciated error effect when a HydraulicLossGreen error is received on the fromHydraulic feature, a transition to the Failed state with PartialSymmetricalWBLossAnunciated error effect when a HydraulicLossComponents error is received on the fromHydraulic feature, and a transition to the Failed state with TotalWBLossUnanunciated error effect when any functional error is received on the fromBSCU feature. The Failed state of NormalBrakeSystem has an associated occurrence distribution following a Poisson distribution with a probability value of 1.0e-4, calculated in accordance with AIR6110 guidance. For the DecelerateOnGround.basic implementation, the Failed state of the alternate brake subcomponent and the Failed state of the emergency brake subcomponent each have an associated occurrence distribution following a Poisson distribution with a probability value of 5.0e-3, per AIR6110 guidance. Composite error behavior for the DecelerateWheels.basic implementation defines two distinct Failed state effects tied to the state of the decelerateonground subcomponent and incoming error state on the fromAlert feature: a Failed state with TotalWBLossUnAnunciated effect is triggered when the decelerateonground subcomponent enters Failed state with no concurrent functional error present on the fromAlert feature, and a Failed state with TotalWBLossAnunciated effect is triggered when the decelerateonground subcomponent enters Failed state concurrently with any functional error present on the fromAlert feature. Hazard classifications per ARP4761 are assigned to each defined failure state of DecelerateWheels, aligned exactly to specified state bindings. The Failed.TotalWBLossAnunciated state is associated with the hazard describing unannunciated total loss of wheel braking, cross-referenced to AIR6110 page 36, applicable during Landing and Rejected Takeoff flight phases, classified as Hazardous with a Remote qualitative probability objective, describing a scenario where crew detects brake failure only when the brakes are operated, then uses maximum available spoiler and thrust reverser capability, with potential for runway overrun. The Failed.TotalWBLossUnanunciated state is associated with two property assignments: first, the hazard describing annunciated total loss of wheel braking, cross-referenced to AIR6110 page 36, applicable during the Landing flight phase, classified as Hazardous with a Remote qualitative probability objective, describing a scenario where crew is aware of brake failure prior to landing, allowing diversion to a suitable airport, notification of emergency ground support, and occupant preparation for overrun while using maximum available spoiler and thrust reverser capability; second, an occurrence distribution following a Poisson distribution with a probability value of 5.0e-7, defined per AIR6110 guidance. The Failed.PartialSymmetricalWBLossUnAnunciated state is associated with the hazard describing unannunciated partial symmetrical loss of wheel braking, cross-referenced to AIR6110 page 36, applicable during Landing or Rejected Takeoff flight phases, classified as Hazardous with a Remote qualitative probability objective, describing a scenario where crew detects partial symmetrical brake loss upon brake application, uses maximum available braking, spoiler, and thrust reverser capability, with risk of brake overheating, wheel or fire failure, and potential runway overrun, with an attached note indicating potential catastrophic effect pending further analysis. The Failed.PartialSymmetricalWBLossanunciated state is associated with the hazard describing annunciated partial symmetrical loss of wheel braking, cross-referenced to AIR6110 page 36, applicable during the Landing flight phase, classified as Major with a Remote qualitative probability objective, describing a scenario where crew is aware of partial symmetrical brake loss prior to landing, uses maximum available deceleration devices, with risk of brake overheating and potential runway overrun.
